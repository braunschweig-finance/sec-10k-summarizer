# Screener and global navigation: baseline review

Date: 2026-11-08. Independent, preimplementation UX/accessibility audit; **not final approval**.

Canonical rules read from `C:\Users\Jacob\OneDrive\Homework\sec-10k-summarizer\AGENTS.md`. Scope: source inspection of `web/app/{layout.tsx,page.tsx,screener/page.tsx,globals.css}` and `web/components/{Terminal.tsx,Screener.tsx}`. No browser, network, dependencies, builds or runtime checks. Findings below distinguish existing source behavior from risks introduced by the planned change. Rendered sizing, contrast, focus and assistive-technology behavior remain unverified. UI/UX skill review guidance informed the accessibility checks; no design-system generation was needed.

## Baseline worth preserving

- Both pages already have a main landmark and a primary heading. Root layout sets English and the screener has route-specific metadata.
- Screener filters have explicit labels and use native inputs/selects. Sorting uses buttons inside column headers with `scope` and `aria-sort`.
- Loading has a status region; errors have an alert and retry. Preview offline, missing snapshot and no matches have distinct messages. No invented preview rows are shown.
- Rows retain filing links, cached price dates, grade/upside caveats, signed values and low-confidence labels. Preserve these when changing presentation.

## Concrete risks and small acceptance criteria

Priority describes implementation attention, not a measured conformance verdict. File references use unique source anchors so they remain useful as lines move.

| Priority / risk | Source evidence and consequence | Acceptance criterion |
|---|---|---|
| High: inconsistent global orientation | `layout.tsx` renders only `{children}`. Terminal's hero contains `Screener →`; Screener has two Terminal return links. Adding shared navigation without reconciling these creates competing entry points and mixed Analyze/Terminal terminology. | Both `/` and `/screener` expose the same named navigation landmark with real **Analyze** (`/`) and **Screener** (`/screener`) links. Exactly the current destination has `aria-current="page"`, including `/?ticker=CAT`. Current state is distinguishable beyond color. Remove or deliberately relabel redundant page-local navigation. |
| High: navigation semantics and focus | Both components already own `<main>`; a layout wrapper could accidentally nest a second main. No skip link exists. A sticky header could cover focused controls or headings. | Keep one main per page; add a keyboard-visible skip link targeting it. Global links precede page controls in logical Tab order and work with Enter, normal link opening and browser Back. Focus remains visible and unobscured. If navigation collapses, its toggle has an accessible name, expanded state and reliable keyboard close behavior; two visible links are sufficient without a menu. |
| High: mobile table hides essential context | Screener table has `min-w-[1020px]` inside `overflow-x-auto`; sources are the last column. Global `body` has `overflow-x: hidden`, which can conceal layout overflow. Sorting exists only in table headers. | At 320px and 375px widths, page navigation, filters and pagination fit without clipped content. A mobile card/list alternative must retain every field, field label, filing link, price date and caveat, plus an accessible sort field and direction control. If retaining the table, provide a discoverable, named, keyboard-operable scroll region and a visible scroll cue; confine horizontal scrolling to that region. |
| High: caveats require hover | `na`, Pay Efficiency cells, low-confidence badge and valuation `src` rely partly or entirely on `title`; footer explicitly says “hover a cell.” Touch users cannot reliably retrieve missing reasons or valuation source. | A tap and keyboard path exposes missing-value reasons, signed Pay Efficiency explanation, low-confidence explanation and valuation source text. Do not hide these only in a desktop table or tooltip. Sources remain associated with the same company and metric; absent sources/values remain honestly absent. |
| High: stale results look actionable | Fetch effect retains `data` while loading. The old table and pagination remain visible; `aria-busy` is on the table wrapper, while page numbers use new local state and row ranges use old response state. | During a deliberately delayed filter/sort/page request, visible results are clearly identified as updating and do not imply the new request has completed. Count, page, range and rows agree once settled. Rapid changes cannot show an older response as current. Status is announced without moving focus on each keystroke. Preserve retry and the distinct offline/unavailable/no-match states in mobile presentation. |
| Medium: route changes lose working context | Screener filters/sort/page live only in component state; row links use `/?ticker=...`. Terminal reads ticker query once on mount. Global links can remount these pages; a different client navigation approach also needs ticker regression coverage. | Verify opening a company loads that ticker, and the global Analyze link does not submit a ticker search. Define Back behavior: preferably restore screener filters, sort, page and position after opening a result; if reset is intentional, make that behavior explicit. Check direct links, reload and Back/Forward. No persistence mechanism is mandated by this audit. |
| Medium: mobile target size and focus styling | Ticker/source links and sort buttons have little direct padding; source links use `text-xs`. Filters use `outline-none focus:border-brass`, while global CSS supplies a focus-visible outline. Actual cascade and target bounds need rendering. | Aim for 44px touch targets for nav, sort, source/detail actions and pagination, with spacing to avoid adjacent activation. Verify visible focus on every control, including inputs/selects, rather than assuming the global outline wins. Check text and focus contrast against actual backgrounds. |
| Medium: narrow filters and duplicate controls | Filter form stays two columns below `sm`; long sector options and uppercase metric labels compete for narrow space. A separate mobile sort UI could leave hidden desktop controls in the accessibility tree. | Long company/sector names and labels wrap without overlapping controls at 320px and at 200% text enlargement. At 400% zoom, navigation and filters reflow. Each visible control has a unique associated label; hidden alternate views are not focusable or announced. Sort field/direction stays consistent across breakpoint changes. |
| Medium: navigation versus Analyze action | Terminal's submit button already says “Analyze”; its ticker input's explicit label is only `$`. Repeating Analyze in global navigation can make the two actions hard to distinguish by context. | Put global Analyze in navigation and keep the company action in its form. Give the ticker input a meaningful accessible name such as “Company ticker”; preserve Enter-to-submit. Screen-reader navigation should distinguish the route link from the submit button. |

## Supervisor validation after implementation

These are requested checks, not checks performed by this audit:

1. Exercise `/`, `/?ticker=CAT` and `/screener` at desktop, 375px and 320px; inspect long names, long source/caveat text, 200% text enlargement and 400% zoom. Confirm no clipped focus or page-level horizontal overflow.
2. Use keyboard only: skip link, both global destinations, filters, sort, company link, source/detail controls, retry and pagination. Confirm focus survives responsive changes and is not stolen by loading announcements. Inspect landmarks, current page, labels and sort state with a screen reader.
3. With controlled existing fixtures or supervisor-provided test data, exercise initial load, delayed refresh, rapid filter changes, error/retry, unavailable snapshot, no match, missing metrics and low-confidence rows. Compare mobile and desktop fields/sources for the same row. Do not call live services for this audit.
4. Check company navigation and Back/Forward behavior with nondefault filters and a later results page. Run the relevant project checks under supervisor ownership; independent implementation review remains required.

No financial methods, source data, credentials or production configuration were reviewed or changed. This document sets review targets; it does not certify the planned implementation or the current application as accessible.
